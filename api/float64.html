float64 #

Error-free transformations and double-double accumulators.

Plain f64 accumulation discards low-order bits at every step. The routines in this file keep the discarded part in a second f64 (a "double-double" value hi+lo with roughly 106 bits of precision), so sums and dot products stay accurate on inputs where naive left-to-right evaluation cancels catastrophically. They are the building blocks for correctly rounded elementary functions (see vlang/vsl#65).

acos returns acos(x) rounded from the double-double evaluation.

fn acos_dd #

fn acos_dd(x f64) (f64, f64)

acos_dd returns acos(x) as a double-double pair (hi, lo), computed as pi/2 - asin(x). For |x| > 1 it returns NaN, like math.acos.

fn expm1_dd #

fn expm1_dd(x f64) (f64, f64)

expm1_dd returns e^x - 1 as a double-double pair (hi, lo). It uses a dedicated e^r - 1 series after the ln(2) range reduction: computing exp_dd(x) first and subtracting 1 loses the last bit exactly in the hard cases the directed search found (x ~ 1e-16), because the exp pair near 1 has ~1e-33 absolute error while e^x - 1 is ~1e-16 there.

fn log1p_dd #

fn log1p_dd(x f64) (f64, f64)

log1p_dd returns log(1 + x) as a double-double pair (hi, lo). Near zero it uses the atanh series with 2 + x formed exactly as a double-double; away from zero it forms 1 + x exactly with two_sum and corrects log(s) by the residual. For x < -1 it returns NaN and for x = -1 it returns -inf, like math.log1p.

fn new_guarded_vector #

fn new_guarded_vector(data []f64, inc int) ([]f64, []f64, []f64)

new_guarded_vector allocates a new slice and returns it as three subslices. v is a strided vector that contains elements of data at indices i*inc and nan elsewhere. frontGuard and backGuard are filled with nan values, and their backing arrays are directly adjacent to v in memory. The three slices can be used to detect invalid memory reads and writes.

sin_dd returns sin(x) as a double-double pair (hi, lo). The argument reduction is double-double accurate for |x| <= 1e15; beyond that (and for non-finite inputs) it falls back to the libm value with lo = 0.

fn sum_dd #

fn sum_dd(x []f64) (f64, f64)

sum_dd returns the double-double sum (hi, lo) of x: the exact sum of the inputs rounded to a hi part, with lo holding the residual. hi + lo approximates the true sum with roughly 106 bits of precision.

fn tan #

fn tan(x f64) f64

tan returns tan(x) rounded from the double-double evaluation.

fn tan_dd #

fn tan_dd(x f64) (f64, f64)

tan_dd returns tan(x) as a double-double pair (hi, lo), computed as sin_dd / cos_dd with the same reduction domain and fallback as sin_dd.

fn tanh #

fn tanh(x f64) f64

tanh returns tanh(x) rounded from the double-double evaluation.

fn tanh_dd #

fn tanh_dd(x f64) (f64, f64)

tanh_dd returns tanh(x) as a double-double pair (hi, lo), computed as (1 - d) / (1 + d) with d = e^(-2|x|): no overflow at any magnitude, and d underflows to 0 exactly when tanh rounds to +-1.

fn two_prod #

fn two_prod(a f64, b f64) (f64, f64)

two_prod returns (p, e) with p = fl(a * b) and p + e == a * b exactly, using Dekker's splitting (no FMA required).

fn two_sum #

fn two_sum(a f64, b f64) (f64, f64)

two_sum returns (s, e) with s = fl(a + b) and s + e == a + b exactly, for any a and b (Knuth's TwoSum, no ordering requirement).
