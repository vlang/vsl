The scientific engine under V computing.

VSL is the V Scientific Library — linear algebra, FFT, statistics, differentiation, optimization and machine-learning primitives, with SIMD kernels and optional OpenBLAS, LAPACKE, CUDA and Vulkan backends. It is the backend that powers VTL tensors.

Start computing Browse the API

Linear algebra in a dozen lines

Matrices, solvers and decompositions with a typed API — no C toolchain required for the pure-V path.

# install the module
v install vsl

// main.v — build and read a matrix
import vsl.la as la

fn main() {
    mut a := la.Matrix.new[f64](2, 2)
    a.set(0, 0, 1.0)
    a.set(1, 1, 2.0)
    println(a.get(1, 1)) // 2.0
}

One library, the whole scientific stack

VSL is organized as focused modules that compose — the same kernels serve direct users and VTL's tensor operations.

Linear algebra & BLAS

vsl.la, vsl.blas and vsl.lapack: dense matrices, solvers, least squares, eigensolvers — SIMD-vectorized pure-V kernels with optional OpenBLAS/LAPACKE acceleration.

vsl.la →

Transforms & calculus

vsl.fft for spectral work, vsl.deriv and vsl.diff for numerical differentiation (GSL-inspired), plus integration and interpolation helpers.

vsl.fft →

Statistics & ML primitives

vsl.dist, vsl.metrics, vsl.ml and vsl.model_selection: distributions, histograms, evaluation metrics and classic model building blocks.

vsl.ml →

Geometry & quaternions

vsl.gm and quaternion support for 3D work, alongside graph algorithms in vsl.graph and data I/O in vsl.inout.

vsl.gm →

Accelerators

Optional CUDA and Vulkan compute paths, MPI parallelism, and a multi-backend compute layer — enabled explicitly, never silently assumed.

The tensor frontend

VTL builds N-dimensional tensors, autograd and neural networks on top of these kernels — NumPy/PyTorch-style computing with VSL underneath.
